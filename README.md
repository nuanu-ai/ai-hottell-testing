## Быстрый запуск дашборда

Нужны Go 1.27.1, Python 3 и Docker Compose.

```sh
gh repo clone nuanu-ai/ai-hottell-testing
cd ai-hottell-testing
docker compose -f local/docker-compose.yml up -d
sh ui/start-local.sh
```

- http://127.0.0.1:8801 — «Живые данные», Hooks + OTel, пульс.
- http://127.0.0.1:8800 — «Глубокий разбор»; без собственных отчётов пустой.
- Данные каждого тестировщика остаются на его машине в игнорируемом `local-data/`.
- Docker запускает приёмник, но сам не подключает хуки агентов: настройка описана в
  [local/README.md](local/README.md) и [hottell/README.md](hottell/README.md).

## Установка и откат конфигов

Перед установкой сборщика прочитайте [local/README.md](local/README.md).
`hottell install` автоматически сохраняет четыре исходных конфига агентов в
`~/.config/hottell-backups/` и выводит путь. Если бэкап не удался, установка останавливается.
`uninstall` оставляет OTel-настройки; полный откат — `hottell restore -backup <каталог>`.
Команда заменяет конфиги целиком; перед восстановлением сохраняет их текущую версию.
Бэкапы, созданные после старой установки, не восстанавливают состояние до неё.

## Коуч и локальный MCP

Новая реализация находится в `temp/`, а не в старом прототипе `hottell/`:

```sh
mkdir -p local-data/bin
(cd temp && go build -o ../local-data/bin/hottell-coach ./cmd/hottell)
local-data/bin/hottell-coach mcp-local
```

Последняя команда запускает MCP по stdio; его подключают как команду MCP в агенте.
Передайте `HOTTELL_DATA_DIR` с абсолютным путём к `local-data` этой копии репозитория
(подробный контракт — [temp/docs/specs/hottell-contract/mcp.md](temp/docs/specs/hottell-contract/mcp.md)).
Skill коуча — [analytics/coach/SKILL.md](analytics/coach/SKILL.md).
`hottell-coach install` требует уже подключённого удалённого MCP hottell; автономный локальный
дашборд его не предоставляет. Для `/api/status` нужен установленный новый hottell;
со старым бинарём или без сервиса статус будет `not_configured`.

# AI Hottell

Сбор данных сессий и полезные выводы о работе человека с AI.

Проект Александра Саломатова и Евгения Клепова на ONYX Camp, 29 сентября 2026 года. Сборщик и локальный приём телеметрии находятся в [`hottell/`](hottell/README.md) и [`local/`](local/README.md). Локальные отчёты и dashboard — в [`dashboard/`](dashboard/README.md).

[План AI Hottell 2.0 для согласования](docs/plan/hottell-2.0.md).

[HTML-коммит команды](docs/commitment.html) — скачать и открыть в браузере. [Опубликованный коммит в чате кемпа](https://t.me/c/4361961701/61).

## Цель

Собрать повторяемый процесс: получать данные реальных сессий, складывать их в небольшой датасет и находить конкретные улучшения работы с агентами. Первый источник — Codex. Первые кейсы — задачи Александра, в том числе поддержка и административные процессы.

Это самостоятельная тема сбора и анализа сессий. Сравнение агентных систем (Eval) остаётся отдельным проектом кемпа.

## Как работаем

1. Проверяем, какие метрики сессий доступны, и делаем дополнительный skill для извлечения контекста задачи и результата.
2. Сохраняем задачу, результат, затраты и затруднения в единый датасет.
3. Изучаем готовые референсы и выбираем способы выявлять повторные ошибки, лишние шаги и возможности автоматизации.
4. Предлагаем изменения процесса или skill; человек выбирает данные для передачи в командный хаб.

## Результат за четыре дня

Предлагаемый минимум MVP из коммита команды:

- Повторяемый сборщик и датасет с реальными примерами выбранных сессий.
- Анализ с метриками, обоснованными выводами и конкретными рекомендациями.
- Skill извлечения контекста и предпросмотр пакета для командного хаба.

Демо: реальная сессия → запись в датасете → метрики и обоснованный вывод → предложение улучшения → выбор пакета для хаба. Повторяем тот же процесс на другой сессии по инструкции.

Смотрим на время до результата, токены, повторные циклы и достижение цели. Отсутствующие данные отмечаем явно. Способ оценки качества результата пока открыт.
