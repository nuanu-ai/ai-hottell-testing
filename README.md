# AI Hottell — свой сервер и клиент для команды

Полный публичный комплект для телеметрии Claude Code и Codex: сервер, веб-интерфейс,
PostgreSQL, ClickHouse, OpenTelemetry Collector и клиент **v0.3.6 для macOS** (Apple
Silicon и Intel). Каждый участник подключает свой агент к серверу команды.

Исходники перенесены из актуального `camp`, коммит `76da83c`, от 2 октября 2026.
Комплект обновлён 7 октября 2026. Точный состав и отличия — [SOURCE.json](SOURCE.json).
Лицензия [MIT](LICENSE): можно самостоятельно устанавливать, изменять и распространять.
Доступ к закрытому репозиторию, нашим аккаунтам или серверу для установки не нужен.

## Первый запуск

На Linux-сервере нужны Git, curl, OpenSSL и Docker с Compose v2. Для планирования небольшой
установки выделите 2 CPU, 6 ГБ RAM и 20 ГБ свободного диска; расход диска зависит
от объёма сессий. Go и Node на хосте не нужны: приложение собирается внутри Docker.
При первой сборке нужен интернет для открытых образов, зависимостей и клиента.

```sh
git clone https://github.com/nuanu-ai/ai-hottell-testing.git
cd ai-hottell-testing
./scripts/setup.sh
```

Скрипт создаёт приватный `.env` со случайными паролями баз. Повторный запуск
сохраняет существующий файл. В `.env` заполните:

```dotenv
HT_BOOTSTRAP_EMAIL=you@example.com
HT_BOOTSTRAP_NAME=Ваше имя
HT_BOOTSTRAP_PASSWORD='ваш-длинный-уникальный-пароль'
```

Пароль первого пользователя должен содержать 8–128 символов. Затем:

```sh
docker compose up -d --build
docker compose run --rm migrate user create-first
curl --retry 20 --retry-delay 1 --retry-all-errors -fsS http://localhost:8080/readyz
```

Откройте **http://localhost:8080** и войдите с этим email и паролем. После создания
пользователя очистите `HT_BOOTSTRAP_PASSWORD` в `.env` и повторите
`docker compose up -d`, чтобы убрать его из контейнера миграций.

По умолчанию интерфейс доступен только на самом сервере. Для первой проверки
удалённой машины используйте SSH-туннель:

```sh
ssh -L 8080:127.0.0.1:8080 user@your-server
```

Базы и коллектор доступны внутри Docker, их порты наружу не открыты. Самостоятельный
сервер работает на Linux; готовые агентские клиенты в этом комплекте — для macOS.

## Доступ команды через HTTPS

Направьте DNS своего домена на сервер и откройте входящие TCP-порты 80 и 443.
В `.env` укажите реальные значения:

```dotenv
HT_DOMAIN=metrics.example.com
HT_PUBLIC_ORIGIN=https://metrics.example.com
HT_COOKIE_SECURE=true
HT_WEBAUTHN_RP_ID=metrics.example.com
COMPOSE_FILE=compose.yaml:compose.https.yaml
```

```sh
docker compose up -d --build
```

Дополнительный контейнер Caddy автоматически получает TLS-сертификат и передаёт
запросы приложению. `HT_PUBLIC_ORIGIN` должен совпадать с адресом, который открывают
участники: он используется в приглашениях, MCP и адресах загрузки. При размещении
за своим HTTPS-прокси используйте только основной `compose.yaml` и те же параметры
origin, secure-cookie и RP ID; прокси должен передавать запросы на порт приложения
и поддерживать длительные ответы MCP.

## Пользователи и подключение агентов

1. В разделе **Пользователи** создайте приглашение. Скопируйте ссылку и передайте
   участнику самостоятельно: автоматической отправки email нет. Приглашение
   действует 7 дней, участник задаёт собственный пароль.
2. Каждый участник входит в свой аккаунт, открывает **Подключение**, выпускает
   личный MCP-ключ и добавляет сервер `hottell` в Claude Code или Codex по инструкции
   этой страницы. Не публикуйте ключи.
3. На Mac участника скачайте установщик с **вашего** сервера:

   ```sh
   curl -fsSL https://metrics.example.com/install.sh -o /tmp/hottell-install.sh
   sh /tmp/hottell-install.sh
   ~/.local/bin/hottell version
   ~/.local/bin/hottell status --json
   ```

4. Выполните оставшиеся шаги установщика и перезапустите открытые сессии агентов.
   Создайте короткую новую сессию и проверьте её появление в аналитике сервера.

После сборки сервер хранит установщик и обе архитектуры клиента внутри образа;
их скачивание участниками не требует GitHub-авторизации. Клиент ставит хуки,
нативный OTel, фоновую службу, локальный MCP и skills. Перед рабочими сессиями
проверьте **Что отправлять**: по настройкам сервер может получать промпты,
содержимое инструментов и транскрипты. Телеметрия передаётся по мере работы агента. Пульс и лента активной сессии читают
свежие события; сводная аналитика обновляется примерно раз в 5 минут, а при
перестроении может показывать данные до 10 минут давности.

Это один сервер для доверенной команды. В текущей версии нет разграничения ролей:
вошедшие пользователи имеют доступ к общей аналитике и управлению пользователями.
Для независимых команд используйте отдельные установки.

[Подробно об установке Mac-клиента, автоматическом бэкапе конфигов и откате](docs/mac-client.md).

## Обновление, остановка и резервная копия

Данные хранятся в Docker-томах PostgreSQL и ClickHouse. Сначала сделайте бэкап,
затем обновите исходники и пересоберите приложение:

```sh
./scripts/backup.sh
git pull --ff-only
docker compose up -d --build
```

Миграции применяются автоматически перед запуском API. Бэкап ненадолго останавливает
весь комплект, архивирует обе базы в согласованном состоянии, сохраняет `.env` и
контрольные суммы, затем снова запускает контейнеры. Каталог `backups/` содержит
пароли и данные команды: храните копию отдельно, не публикуйте её и ограничьте доступ.

Восстановление делайте в новую установку с пустыми томами. Скопируйте `.env` из
бэкапа в новый checkout, при необходимости измените домен/порт, сохраняя пароли баз:

```sh
./scripts/restore.sh /absolute/path/to/backup
docker compose up -d --build
```

Восстановление проверяет суммы и отказывается перезаписывать непустые тома.
Для восстановления старого бэкапа используйте также соответствующую версию кода
из его `SOURCE.json`. Остановка, освобождающая память и сохраняющая данные:

```sh
docker compose down
```

**Не добавляйте `-v`** к этой команде: он удаляет базы. TLS-сертификаты Caddy
в приведённый бэкап баз не входят; на новой машине Caddy получает их заново.

## Проверка и диагностика

```sh
docker compose ps
docker compose logs --tail=100 app migrate collector
curl --retry 20 --retry-delay 1 --retry-all-errors -fsS http://localhost:8080/readyz
```

Успешный запуск контейнеров подтверждает запуск сервера. Приём данных проверяйте
по новой сессии подключённого агента в интерфейсе. Не отправляйте полные логи,
`.env`, ключи или payload сессий в публичные issues.

В комплект включены исходники API, клиента, интерфейса, схемы БД и миграции;
личные сессии, закрытые deployment-файлы и фикстуры исходного проекта не перенесены.

Комплект проверен 7 октября 2026 в отдельных Linux-контейнерах: сборка интерфейса
с проверкой типов и линтером, сборка API, миграции пустых баз, первый вход,
приглашение второго участника, MCP-ключ, приём синтетических OTLP-событий,
живой пульс и сводная аналитика, загрузка обеих архитектур клиента с проверкой SHA256,
бэкап и восстановление аккаунта и сессии в пустые тома. HTTPS-конфигурация проверена;
получение сертификата на внешнем домене зависит от ваших DNS и сетевого доступа.
