# Инцидент 2026-10-01: установка hottell заблокировала Claude Code и Codex на машине владельца

Статус: закрыт. Исправления в `hottell-v0.2.2`; сквозная проверка HT-104 на той же машине пройдена.
Время — местное (WITA, UTC+8).

## Итог

Живая проверка HT-104 поставила новый `hottell` на настоящую машину
владельца. Новый бинарь лёг по пути `~/.local/bin/hottell`, на который
уже ссылались хуки прежнего прототипа hottell в формате
`hottell -agent claude|codex`. Новый бинарь не знает `-agent`, печатает
usage и выходит с кодом 2. Для хуков агентов код 2 означает «заблокировать».
Хуки пользовательского уровня действуют на все сессии, поэтому на машине
перестали работать все сессии Claude Code и, по всей видимости, Codex:
отклонялся каждый вызов инструмента и каждый промпт, а хук `Stop` не давал
агенту закончить ответ. Перезагрузка не помогла, потому что конфиги
остались прежними. Машина была непригодна для работы с агентами
примерно 30 минут.

## Причины

1. **Новый бинарь на месте старого, а старые вызовы остались.** `install`
   проверяет только свои записи. Чужие хуки, которые указывают на тот же
   путь `~/.local/bin/hottell`, он не замечает.
2. **Код выхода 2 при неизвестных аргументах.** Для CLI это норма, а для
   хука это блокировка. Обещание «хук всегда выходит с 0» выполняется только
   при вызове `hottell hook …`. Любой другой вызов из хука ломает агента.
3. **Проверку провели на настоящей машине.** Задание это запрещало. Владелец
   разрешил по запросу оркестратора, но риск со старыми хуками оркестратор
   видел и до установки их не убрал.
4. **Откат оказался недоступен:**
   - копии лежали в `/private/tmp` и пропали при перезагрузке;
   - исправить могли только руками владельца, потому что все агенты на
     машине были заблокированы;
   - готовой команды отката, которую можно запустить без агента, не было.
5. **У оркестратора нет выхода из цикла.** Одинаковая блокировка
   повторилась 178 раз, а он не остановился и не перешёл к одному
   ожиданию без опроса.

- Данные телеметрии и код в `main` не пострадали.
- При разборе в журнал сессии попал токен коллектора локального стенда.
  Он перевыпущен в шаге 6 HT-104, старый отозван.

## Исправления

- [x] **HT-108.** Вызов `-agent claude|codex` обрабатывается как
      `hook claude|codex`. Любой вызов, который начинается с флага, — это
      вызов хука с кодом 0.
- [x] **HT-112** (требование владельца: что бы ни случилось с бинарём, агент
      не должен этого заметить). Команда хука —
      `'<бинарь>' hook <agent> >/dev/null 2>&1 || true`, на каждом хуке
      таймаут 10 с (на SessionEnd и Interrupt — 1 с). Код всегда 0, stdout
      пуст: и когда бинаря нет, и когда он выходит с кодом 2 или печатает
      решение `block`.
- [x] **HT-109.** `install` находит чужие хуки на тот же путь и без
      `--replace-foreign-hooks` не ставится; с флагом снимает их после копии
      конфигов и до замены бинаря. Если проверить конфиг не удалось,
      установка останавливается. Краевые случаи разбора команды — HT-114.
- [x] **HT-110, HT-113.** Перед каждой записью в конфиг агента копии
      сохраняются в `~/Library/Application Support/hottell/backup/<время>/`,
      копии переживают `uninstall`. `hottell restore` откатывает без сети и
      без агента; перед откатом делает копию для отмены.
- [x] **Тесты.** Установка поверх хуков прототипа; команда хука на живом
      `sh` для случаев «бинаря нет / блокирует / работает».
- [x] **Процесс.** Исполнители проверяют установку только во временном
      `HOME`. На настоящей машине HT-104 прошла с копиями конфигов и
      `hottell restore` наготове; агенты работали всё время установки.
- [x] **Токен коллектора** перевыпущен.
- [ ] **Оркестратор:** останавливаться после второй одинаковой блокировки
      хука. Это поведение агента-оркестратора, а не кода hottell. После
      HT-112 хук hottell больше не может его вызвать.

## Как откатить вручную, если повторится

Агентов в это время не запускать: их хуки будут блокировать.

Сначала проще всего `~/.local/bin/hottell restore` (HT-110) или
`~/.local/bin/hottell uninstall`. Если бинарь не запускается, скрипт ниже
делает то же для хуков. Он сначала сохраняет копию каждого файла рядом
(`.bak-<время>`) и удаляет только хуки, у которых первое слово команды —
путь `~/.local/bin/hottell`, в кавычках или без. Хуки других программ,
где слово «hottell» встречается иначе, он не трогает.

```sh
python3 - <<'EOF'
import json, os, shlex, shutil, time
binary = os.path.expanduser("~/.local/bin/hottell")
def ours(command):
    # An unquoted leading ~/.local/bin/hottell is our binary, as the shell expands
    # it; a quoted or escaped ~ stays literal.
    rest = command.removeprefix("~/.local/bin/hottell")
    if rest != command and (rest == "" or rest[0] in " \t"):
        return True
    try:
        words = shlex.split(command)
    except ValueError:
        return False
    return bool(words) and words[0] == binary
stamp = time.strftime("%Y%m%d-%H%M%S")
for p in ("~/.claude/settings.json", "~/.codex/hooks.json"):
    p = os.path.expanduser(p)
    if not os.path.exists(p):
        continue
    shutil.copy2(p, p + ".bak-" + stamp)
    d = json.load(open(p))
    hooks = d.get("hooks", {})
    for event in list(hooks):
        groups = []
        for g in hooks[event]:
            kept = [h for h in g.get("hooks", []) if not ours(h.get("command", ""))]
            if kept:
                groups.append({**g, "hooks": kept})
        if groups:
            hooks[event] = groups
        else:
            del hooks[event]
    with open(p, "w") as f:
        json.dump(d, f, indent=2, ensure_ascii=False)
    print("cleaned", p, "backup", p + ".bak-" + stamp)
EOF
launchctl bootout gui/$(id -u)/dev.alva.hottell 2>/dev/null
rm -f ~/.local/bin/hottell ~/Library/LaunchAgents/dev.alva.hottell.plist
```
