# Когда изменения хуков и нативного OTel вступают в силу

Эксперимент HT-78 (эпик HT-76). Цель — точно знать, когда живая сессия
агента подхватывает изменения, которые фоновый процесс `hottell` вносит
в конфиги. По этой таблице страница настроек и MCP сообщают пользователю,
когда запрет начнёт действовать.

Дата: 2026-10-01. Версии: Claude Code 2.1.285, Codex CLI 0.159.0, macOS.

## Как проверяли

- Интерактивные сессии запускал владелец. Конфиг меняли, пока сессия
  была открыта, затем отправляли в неё следующий промпт.
- **Хук** — команда, которая при срабатывании оставляет след. «Изменение» —
  замена команды существующего хука на другую.
- **OTel** — отправка на локальный стенд. «Изменение» — смена
  `OTEL_LOG_USER_PROMPTS` у Claude и `log_user_prompt` у Codex; результат
  виден по наличию текста промпта в событии (`claude_code.user_prompt`,
  `codex.user_prompt`).
- Для каждой строки сравнивали две точки: следующий промпт в уже идущей
  сессии и новую сессию (у Codex — новый запуск `codex exec`)
  с тем же файлом.
- Доверие к хукам Codex записывалось хэшем по [codex-trust.md](codex-trust.md)
  (HT-77); `/hooks` Codex не запрашивал.

## Выводы

- **Claude Code, хуки.** Claude Code перечитывает `hooks` из
  `~/.claude/settings.json` в идущей сессии. Добавление, замена
  и снятие хука бинарём действуют со следующего события без действий
  пользователя.
- **Claude Code, OTel.** Экспортёры OTel создаются при старте сессии.
  Изменения `env`, в том числе адреса, заголовка и категорий содержимого,
  идущая сессия не подхватывает. Смена адреса (`OTEL_EXPORTER_OTLP_ENDPOINT`)
  отдельно не проверялась: адрес в C3 добавлялся вместе с остальными
  ключами и так же подействовал только в новой сессии.
- **Claude Code, проектные настройки.** `OTEL_*` из `.claude/settings.json`
  и `.claude/settings.local.json` проекта Claude Code 2.1.285 не применяет
  даже при старте новой сессии: действуют только пользовательские
  настройки и окружение. Поэтому запрет папки на нативный OTel Claude
  не действует, см. [native-otel.md](native-otel.md), раздел 4.
- **Codex, хуки и OTel.** Codex читает `hooks.json`, доверие и `[otel]`
  один раз на процесс. Идущая сессия TUI изменений не видит; `codex exec`
  видит их при каждом новом запуске. Для TUI и Codex Desktop нужен
  перезапуск Codex (о долгоживущем `codex-app-server` —
  [native-otel.md](native-otel.md), раздел 5).
- **Codex, изменение хука.** Новая команда меняет хэш хука, поэтому
  бинарь вместе с `hooks.json` переписывает доверие
  ([codex-trust.md](codex-trust.md)); без этого хук молча пропускается.

## Что сообщать пользователю

Запреты хуков (агент, источник `hooks`, событие, поле, папка) и запреты
транскриптов бинарь применяет сам при каждом вызове `hottell hook`
и при чтении транскриптов по сохранённым настройкам. Они действуют сразу
у обоих агентов и от перечитывания конфигов агентами не зависят.
Таблица выше определяет срок только для того, что бинарь меняет
в конфигах агентов: записи хуков (установка, снятие) и нативный OTel.

| Агент | Что бинарь меняет в конфиге | Сообщение |
|---|---|---|
| Claude Code | записи хуков | действует сразу |
| Claude Code | нативный OTel: агент, источник, категория | «с новой сессии» |
| Codex | записи хуков и доверие | «после перезапуска Codex» |
| Codex | нативный OTel: агент, источник, категория | «после перезапуска Codex» |
