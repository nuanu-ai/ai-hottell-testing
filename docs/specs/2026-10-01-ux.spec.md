# AI Hottell — интерфейс: что показываем и как

Дата: 01.10.2026. Относится к дашборду `ui/` (:8801 «живые данные», :8800 «разобранные сессии»). Дизайн-система — нынешняя: токены в `ui/static/index.html` (IBM Plex Sans/Mono, `--accent`, `--ok`, `--warn`, `--bad`, светлая и тёмная темы), компоненты `.kpi`, `.hero`, `.seg`, `.tag`, `.bar`. Новых шрифтов, цветов и библиотек нет. Задание дополняет `2026-10-01-hottell-coach.spec.md` и план `claude/live-honest-fix`, не повторяя их. Данные для новых элементов задаёт задание на коуч, их вид — этот документ. Интерфейсную часть задания на коуч делать по нему. Все три работы правят `ui/static/index.html`, поэтому их выполнять последовательно: план → задание на коуч → этот документ.

## Задача интерфейса

Человек открывает дашборд, чтобы за минуту понять три вещи: что мешает работать с агентами, что с этим сделать и помогло ли уже сделанное. Всё остальное — подробности по запросу. Сейчас первым открывается Skills, главный вывод собран в длинное предложение, а цикл «нашли → обсудили → внедрили → проверили» нигде не виден.

## Общие правила значений

- **Неизвестно — «—», никогда 0.** Оценка — «≈». Сумма по части сессий — тоже «≈» и рядом «у N из M»: «≥» не используется, это не доказанная нижняя граница. Эти правила уже вводит план `live-honest-fix`; держать их во всех новых элементах.
- **Время — местное для браузера.** Сейчас везде UTC («НАЧАЛО, UTC»). Показывать местное время без пометки; UTC — в подсказке `title`. Для сессий старше суток — «30.09 14:22», для сегодняшних — «14:22».
- **Длительности:** «43 м», «2 ч 41 м», «23 ч+» для открытой больше суток сессии.
- **Числа — `tabular-nums`**, тысячи через узкий пробел, деньги «$1.23».
- **ID сессии** — 8 + 4 знака (`01a0f57b…4b74`), моноширинным шрифтом; по клику копируется полный ID.
- **Одна мысль — одна строка.** Заголовки карточек не длиннее 80 знаков, пояснение — одна строка, подробности раскрываются.

## Структура

```
[■ hottell]  [Живые данные | Глубокий разбор]   Что исправить · Обзор · Сессии · Трение · Инструменты и MCP · Skills
[7д 14д 30д Всё] [Все | Claude Code | Codex] [Все проекты ▾] [Без служебных | Все]      ▁▂▅▃▇▂ ● 2 работают   Отправка: работает · Что отправлять →   [Обновить]
```

- Переключатель версий переименовать: «Новые сессии · Hooks + OTel» → **«Живые данные»**, «Разобранные сессии» → **«Глубокий разбор»**. Источник данных — в подсказке.
- Порядок вкладок: **Что исправить** (открывается по умолчанию) · Обзор · Сессии · Трение · Инструменты и MCP · Skills.
- Период по умолчанию — 7 дней.
- Справа во второй строке, слева направо:
  - **Пульс** — новый, см. «Анимация»;
  - **строка отправки** — из пункта 3 задания на коуч;
  - кнопка **«Обновить»** вместо «Пересобрать».

  Надпись «есть новые данные — обновить» заменяется пульсом и тихим обновлением (см. «Анимация»).
- Страницы сервиса команды («Подключение», «Что отправлять», «Пользователи», «Профиль») остаются в веб-интерфейсе сервиса. Дашборд ссылается на них из строки отправки. Объединение двух интерфейсов — отдельное решение.

## Что исправить

Сверху вниз:

1. **Цикл улучшений** — полоса из шести шагов с числами за период. Каждый шаг кликабелен и фильтрует список ниже. Пример с условными числами:

   ```
   Сессии 14 → Сигналы 37 → Темы 3 → Обсуждено 2 → Внедрено 1 → Проверено 0 из 1
   ```

   | Шаг | Значение | Источник |
   |---|---|---|
   | Сессии | Ваши сессии за период (`kind = user`) | `dataset.sessions` |
   | Сигналы | Эпизоды трения в этих сессиях | `friction[].by_session` |
   | Темы | Карточки о работе (без здоровья сбора) | `findings`, `scope ≠ collection` |
   | Обсуждено | Записи журнала коуча за период с любым решением | `GET /api/coach/journal` |
   | Внедрено | Записи с `decision: applied` | там же |
   | Проверено | Записи с итогом; цвет итога — `--ok` / `--warn` / `--ink-3` для «мало данных» | там же |

   Пустой журнал — шаги 4–6 показывают «—» и подсказку «Обсудите первую тему в Codex или Claude Code».
2. **Заголовок и главное действие.** Вместо длинного предложения в `.hero`: «3 темы стоит обсудить» и под ним одна строка — «по 14 вашим сессиям за 7 дней, без глубокого разбора». Справа кнопки **«Обсудить в Codex»** (основная, `--accent`) и **«Обсудить в Claude Code»** (вторичная). Кнопка копирует стартовую реплику и разворачивает под собой строку с командой для терминала и кнопкой «Скопировать».
3. **Строка полноты данных** — из плана (`fix-cov`), сразу под заголовком.
4. **Темы** — до 3 карточек, остальные под «Ещё N». Карточка по умолчанию свёрнута; пример с условными числами:

   ```
   [привычка] Длинные сессии сжимают контекст по 6 раз              15 эпизодов · 7 сессий · ≈ $2.10
   Сжатия идут подряд в одной сессии: 6 за 2,5 ч в 01a0f058…5b9f        [Обсудить в Codex] [в Claude Code] [Не проблема]
   ▸ Доказательства и состояние
   ```

   - Слева тег вида (`.tag`), заголовок и одна строка «почему».
   - Справа — цена: эпизоды, сессии, стоимость эпизодов (не сессий целиком).
   - Ниже — три кнопки. «Обсудить» копирует реплику с id находки.
   - Раскрытие показывает то, что сейчас открыто всегда: доказательства со ссылками, четыре оси состояния, правку и диагностику.
5. **Исправлено** — журнал коуча, новые записи сверху. Пример с условными записями:

   ```
   01.10  Инструкции  ~/.codex/AGENTS.md  Уточнено правило про объём реализации        проверка 08.10
   28.09  Skill       release-evidence-gate  Создан                                      повтора не было на 4 задачах
   ```

   Итог — `.tag`: «повтора не было на N задачах» (`ok`), «повторилось на N из M» (`warn`), «мало данных» (нейтральный), «проверка 08.10» до срока. По клику раскрываются основания, изменение, откат.
6. **Здоровье сбора данных · N** — свёрнуто, из плана (T12).

## Обзор

- **KPI в порядке важности:**
  1. **Ваше время.**
  2. **Агент работал**, с подписью «ещё N ч — по расписанию» (пункт 2.5 задания).
  3. **Ваши сессии.**
  4. **Расходы:** «≈», а при неполных данных ещё и «у N из M».
  5. **Попадание в кэш.**
  6. **Ошибки инструментов** — «среди вызовов с известным исходом (N%)».

  У каждого KPI изменение к прошлому периоду, только если оба значения известны.
- Графики и блоки ниже не меняются. В «Трении» у каждого сигнала — ссылка на тему в «Что исправить», если тема есть.

## Сессии

- **Колонки:** Начало · Агент · Тип (в живых данных) · Проект · Задача · Работа · Реплик · Ошибок · $ · Сигналы.
- **Задача** — первая реплика в одну строку с многоточием, полный текст в подсказке. Сейчас строка разрастается до четырёх строк, и на экран помещается пять сессий; должно помещаться около двадцати.
- **Работа** — `active_min`; время, пока сессия была открыта, — в подсказке.
- **«Исход»** в живых данных не показывать. Служебные строки в режиме «Все» — `--ink-3`.

## Лента сессии

- Заголовок — первая реплика, не больше 2 строк, полностью по раскрытию.
- В строке метаданных: агент, проект, ID (8 + 4), местное время начала и конца, модель.
- Справа от заголовка — «Обсудить эту сессию в Codex / Claude Code» (реплика с id сессии).
- Метка «записан только хвост» — по исправленному правилу (пункт 2.1 задания).
- Если сессия ещё идёт (последнее событие меньше 2 минут назад), в шапке ленты — точка пульса и «идёт сейчас». Новые события дописываются снизу без перезагрузки (см. «Анимация»).

## Skills, Трение, Инструменты и MCP

Структура остаётся.
- **Skills:** заголовок «N skills использовались из M известных».
- **Трение:** колонка «$ в этих сессиях» → «стоимость эпизодов».

Остальное — в плане `live-honest-fix`.

## Анимация: живой процесс

Задача анимации — показать, что система живая и что работа агентов прямо сейчас превращается в данные, а данные — в выводы. Она не должна отвлекать от чтения.

### Пульс (шапка, только «Живые данные»)

```
▁▂▅▃▇▂▁▁▃▅  ● 2 работают · 34 события/мин
```

- **Вид.** 60 столбиков по 2 px с шагом 1 px: последние 10 минут, столбик — 10 секунд. Высота 0–16 px по числу событий хуков, цвет — по агенту, как в `.tag.claude` и `.tag.codex`.
- **Движение.** Раз в 5 секунд справа въезжает новый столбик, ряд сдвигается влево: `transform: translateX`, 400 ms. Точка `.dot` один раз пульсирует (scale 1 → 1.6, opacity 1 → 0, 600 ms), если пришли новые события.
- **Тишина.** Нет событий 2 минуты — столбики гаснут до `--line`, точка серая, текст «тишина 12 мин».
- **Клик** раскрывает список идущих сессий: проект, первая реплика, «12 событий за минуту» и ссылка на ленту.
- **Данные.** Новый `GET /api/pulse` на сервере `ui/` (только loopback), раз в 5 секунд. Ответ: `[{t, agent, n}]` за 10 минут с шагом 10 секунд и `active: [{sid, project, first, last_at, per_min}]`. Запрос к ClickHouse стенда — то же подключение, что у `live.py`:

  ```sql
  SELECT toStartOfInterval(Timestamp, INTERVAL 10 SECOND) t, LogAttributes['agent'] agent, count() n
  FROM otel_logs
  WHERE ServiceName = 'agent-hooks' AND Timestamp > now() - INTERVAL 10 MINUTE
  GROUP BY t, agent ORDER BY t
  ```

  Ответ кэшируется на 5 секунд, чтобы несколько вкладок не нагружали ClickHouse.

### Тихое обновление (обе версии)

Когда пересборка даёт новый `generated_at`, данные подменяются на месте, без кнопки:
- **Числа KPI и шагов цикла** досчитывают от старого значения к новому за 600 ms. Ширина не прыгает благодаря `tabular-nums`.
- **Изменившиеся карточки тем** — левая граница вспыхивает `--accent` и гаснет за 1,2 с.
- **Цикл улучшений.** Если число на шаге выросло, от предыдущего шага к нему проходит точка 6 px (`--accent`, 800 ms).
- **Новая запись журнала** въезжает сверху в «Исправлено», 400 ms.
- **На открытой ленте сессии** новые события дописываются снизу. Если человек прокрутил ленту вверх, вместо автопрокрутки появляется плашка «+N событий ↓».

### Ограничения

- Двигаются только `transform` и `opacity`, вёрстка не сдвигается.
- Одна анимация на элемент за раз.
- Длительности 150, 400, 600 и 800 ms; кривая `cubic-bezier(.2, 0, 0, 1)`.
- `prefers-reduced-motion: reduce` — без движения: столбики обновляются сразу, числа меняются без счёта, вспышек нет. Правило уже есть в `index.html:168`, распространить его на `animation`.
- Скрытая вкладка (`document.visibilityState = hidden`) не опрашивает `/api/pulse` и `/api/dataset`.
- Без новых зависимостей: ванильный JS и CSS в `index.html`.

## Приёмка

- По умолчанию открывается «Что исправить» за 7 дней.
- Цикл улучшений показывает шесть чисел; клики по шагам фильтруют список. При пустом журнале — «—» и подсказка.
- Темы свёрнуты, до 3 на экране, у каждой работают обе кнопки «Обсудить».
- Время местное, UTC в подсказке. Длинные первые реплики занимают одну строку в «Сессиях» и до 2 строк в ленте.
- Пульс двигается во время работы агента и затихает через 2 минуты после последнего события. При `prefers-reduced-motion` движения нет. В скрытой вкладке нет запросов (проверка во вкладке «Сеть»).
- После пересборки числа досчитывают, изменённые карточки вспыхивают, страница не перезагружается и не прыгает.
- «Глубокий разбор» (:8800) работает как раньше, но без пульса и с новым порядком вкладок.

## Для веб-интерфейса сервиса команды

- Корень `/` сейчас перенаправляет на «Пользователей» — это экран администратора. Для обычного пользователя стартовой должна быть «Подключение», пока бинарь не подключён, и «Что отправлять» после этого.
- На «Что отправлять» не хватает сводки сверху: что сейчас уходит одной строкой, например «Отправляется: Claude Code и Codex · хуки, транскрипты, метрики · запрещено: 2 папки». Сейчас понять это можно, только просмотрев все отметки.
