# Содержание дашборда

Что показывает каждый экран, как ранжируется и какие действия доступны. Метрики — [metrics.md](metrics.md). Реализация и вид — техническая часть. Демо на условных данных — [demo/dashboard.html](../demo/dashboard.html).

В MVP три экрана: **Обзор**, **Сессии**, **Рекомендации**. Каждый блок проходит две проверки: данные для него будут в первые недели работы, и человек, посмотрев на него, что-то делает.

Общие правила:

- Сверху — что требует решения человека и что поменять, затем результат. Рекомендация всегда — конкретное действие с готовым изменением и кнопкой «Применить».
- Каждое число кликается до списка сессий, сессия — до шага (вызова, реплики).
- Показываются только подтверждённые эпизоды; неподтверждённые — во входящих.
- Оценочные значения помечены «≈» и подписью, на чём основаны; «нет данных» показывается явно, не нулём.
- Фильтры одной строкой сверху: период (7 / 14 / 30 дней) и агент.

## Обзор

| Блок | Содержание | Правило |
|---|---|---|
| **Шапка** | одна строка: сессий за период · по агентам · без вердикта | [metrics.md §6](metrics.md) |
| **Сэкономлено** | главное число: ≈ ваше время, сэкономленное внедрёнными изменениями за период; работа агента — отдельной строкой, не складывается; полоса по изменениям; подпись «оценка по N сессиям после внедрения». Под ним мелко — нагрузка на человека на подтверждённый результат с числом сессий, доля сессий с разметкой доработки и условие качества | [metrics.md §5.1](metrics.md); изменение без использования или с упавшим качеством даёт 0 с пояснением |
| **Входящие** | вопросы по результату (оранжевые флаги); эпизоды на подтверждение; предложения на решение; сессии, ждущие выбора на отправку, — если выбор делается в дашборде | по числу, клик — в список с действиями |
| **Где плохо** | до 5 проблем простыми словами («Задача без критерия „готово“») и чья она — постановка, агент или рутина; число сессий, потерянное время; предложение одной строкой со статусом и основанием — «по одной сессии» или «повтор в N сессиях»; «показать все» | ранжирование: число сессий с подтверждёнными эпизодами × доля затрат; паттерн без предложения — «предложения нет — разберите сессию» |

Пустое состояние: «Сессий пока нет. Установите сбор и проведите первую сессию» и ссылка на инструкцию.

## Сессии

- **Список** (аналитические сессии не показываются): дата, агент, задача одной фразой, класс, длительность, вердикт (цвет + подпись), число подтверждённых эпизодов, отправка — отправлена / ждёт выбора. Импортированные старые сессии помечены.
- **Сессия**:
  - список ходов: реплика человека с типом из быстрого разбора — ▲ коррекция, △ уточнение, ◇ ответ, ○ смена цели; при уверенности ниже 0.6 — контуром; что сделал агент — краткое содержание хода; ошибки вызовов; сжатия контекста; ожидания разрешений;
  - эпизоды — на своих ходах, с названием паттерна, статусом (подтверждён / ждёт / снят) и ссылками на шаги;
  - вердикт и на чём он основан — пункты критерия с отметкой; мнение модели отдельной строкой; связанные предложения;
  - действия: подтвердить / снять эпизод с причиной; ответить на вопрос о результате; разметка — результат 0–3, доработка в минутах, уровень для командного среза.

## Рекомендации

- **К решению** — карточки. Каждая:
  - действие одной фразой, глаголом: «Добавьте правило в AGENTS.md», «Создайте skill „Сверка возвратов“», «Удалите skill pdf-invoice», «Поставьте проверку перед „готово“», «Почистите AGENTS.md проекта»;
  - почему — одна строка: сколько сессий и сколько времени потеряно; пометка «по одной сессии», если повторов нет;
  - готовое изменение — текст правила, diff, черновик skill или hook — видно до применения;
  - кнопки: **Применить** (подпись по действию: «Создать skill», «Удалить skill», «Поставить hook»), **Скопировать**, **Отклонить**.
- **Применить** — изменение вносит агент человека на его машине, после подтверждения; дашборд файлы не меняет. Применённое уходит в список ниже.
- **Применено** — что, с какой даты, используется ли, эффект до / после, сэкономлено ≈, итог: работает / проверяем / не используется. Не используется 7 дней — подсказка «перепишите или уберите». Здесь же цена контура за период.

## После MVP

Появляются, когда для них есть данные:

- график главной метрики по неделям — после 4 недель данных;
- **Классы задач** — после ≥ 5 сессий на класс: нагрузка на человека, медианы времени и токенов, вердикты, главные паттерны;
- **Команда** — при ≥ 3 участниках со share-pack'ами ([share-pack.md](share-pack.md), [metrics.md §9](metrics.md)): своя позиция относительно медианы команды по практикам, лучшие практики, общие паттерны, профили skills.

Не делаем: пульс активности, отдельный экран паттернов (он повторяет «Где плохо»), отдельный экран настроек — устаревшие настройки и неработающие MCP попадают в «Где плохо» с предложением. Доля снятых эпизодов по детекторам — в отчёте приёмки, не на дашборде.
