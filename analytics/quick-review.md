# Быстрый разбор хода

Автоматический разбор одного хода: **реплика человека → ответ агента**, один вызов модели. Даёт классы реплик и отметки хода. По ним ядро без глубокого разбора считает вмешательства для главной метрики, детекторы D01 и D05 и уточняет D16. Глубокий разбор ([skill/SKILL.md](skill/SKILL.md)) берёт их готовыми.

Для Deep 2.0 разметка хода — только входной сигнал. D05 перепроверяется по всем заданиям и каждому раннему заявлению о готовности согласно [v2_analysis.md](v2_analysis.md); последний ответ не заменяет эту проверку.

## Когда и где

- **Запуск** — хук `Stop`: агент закончил ход. Автоматически и в фоне: человек ничего не ждёт, в рабочей сессии ничего не показывается.
- **Где** — на машине человека: его Codex или Claude Code без интерфейса, под его аккаунтом, быстрая модель. Один вызов модели на ход.
- **Техническая часть** — запуск из хука, защита от рекурсии (запуск разбора сам не собирается и не разбирается), запись результата в MCP.
- **Без модели** — короткие «ок», «да», «продолжай», «спасибо» (до 3 слов из списка, без новых данных) размечаются правилом как `ack` с уверенностью 1. Модель не вызывается.
- **Отправка** — результат уходит вместе с сессией: если сессия не выбрана на отправку, не уходит и он.

## Вход

Не больше ~4 000 токенов.

| Поле | Что | Ограничение |
|---|---|---|
| `turn_index` | номер хода, 0 — постановка | — |
| `task` | постановка — первая реплика сессии | до 500 символов |
| `previous_agent_message` | финальное сообщение агента предыдущего хода | последние 1 000 символов; для хода 0 — нет |
| `prompt` | реплика человека этого хода | до 2 000 символов |
| `tool_summary` | вызовы хода: инструмент, успех, класс ошибки | до 20 строк, без аргументов и выводов |
| `agent_message` | финальное сообщение агента этого хода | последние 1 500 символов |
| `examples` | реплики, класс которых человек исправлял, с верным классом | до 6 примеров, до 600 символов |

## Выход — `turn_review`

Схема — [skill/schemas.json](skill/schemas.json), `$defs/turn_review`. Номер хода и id сессии добавляет запуск.

| Поле | Что | Правило |
|---|---|---|
| `human_turn_class` | класс реплики | `task` для хода 0; дальше — [model.md §3.5](model.md) |
| `confidence` | уверенность, 0–1 | ниже 0.6 — глубокий разбор перепроверяет |
| `instruction` | инструкция о способе работы — пересказ одной фразой, или `null` | «сначала…», «всегда…», «не трогай…»; содержание задачи — суммы, даты, файлы — не инструкция |
| `claims_done` | ответ агента заявляет, что задача выполнена | «готово», «сделал», «отправил»; «сделал черновик, проверь» — нет |
| `ends_with_question` | ход закончился вопросом человеку или просьбой решить | [model.md §3.6](model.md) |
| `summary` | что сделано в ходе | одна фраза до 120 символов |

## Правила

- Один вызов модели; ответ — только JSON по схеме, до ~300 токенов.
- Не задаёт вопросов, не предлагает изменений, не подтверждает эпизоды, не выносит вердикт.
- Сомневаешься — ставишь `confidence` ниже, не угадываешь.

## Кто использует

- Метрики: вмешательства по классам реплик ([metrics.md §1](metrics.md)) — главная метрика считается без глубокого разбора.
- Детекторы: D01 и D05 считает ядро по полям хода; D16 — по `ends_with_question`; D10 — по `instruction` из разных сессий.
- Дашборд: классы реплик и краткое содержание ходов на таймлайне сессии.
- Глубокий разбор: берёт готовое, перепроверяет при `confidence` ниже 0.6, может исправить; исправление человека главнее.

## Цена и качество

- Токены быстрого разбора входят в цену контура ([metrics.md §4](metrics.md)); на дашборде — средняя цена разбора хода.
- Приёмка — [acceptance/semantic.yaml](acceptance/semantic.yaml), разделы `turn_classes`, `claims`, `instructions`.
- Разбор подстраивается под разметку: реплики, класс которых человек исправил, подставляются в промпт как примеры (`examples`).
- Согласие с разметкой человека считается от 10 размеченных сессий, надёжно — от 50; среди размеченных реплик не меньше 30 % исправленных. Порог **не определён**: стартовый ориентир — 80 % по классам реплик, фиксируется после замера (план, шаг A10). Модель выбирается там же по согласию и цене за ход.

## Промпт

```
Ты размечаешь один ход работы человека с агентом. Верни только JSON по схеме turn_review.

Постановка: {task}
Предыдущий ответ агента: {previous_agent_message}
Реплика человека (ход {turn_index}): {prompt}
Вызовы в ходе: {tool_summary}
Ответ агента: {agent_message}
Как человек исправлял классы раньше: {examples}

human_turn_class — для хода 0 «task»; иначе один из:
  correction — агент неверно понял то, что уже было доступно: в постановке, файлах, прошлых репликах;
  clarification — человек добавляет данные, которых не было;
  answer — ответ на вопрос агента;
  goal_change — человек увидел результат и хочет другое;
  new_task — новая задача в той же сессии;
  ack — «да», «ок», «продолжай» без новых данных.
  Не отличить correction от clarification — проверь постановку: данные там были → correction.
instruction — если реплика задаёт способ работы («сначала…», «всегда…», «не трогай…»),
  пересказ одной фразой; инструкции о содержании задачи — суммы, даты, файлы — null.
claims_done — ответ агента заявляет, что задача выполнена; «сделал черновик, проверь» — false.
ends_with_question — ответ заканчивается вопросом человеку или просьбой решить.
summary — что сделано в ходе, одна фраза до 120 символов.
confidence — насколько уверен в human_turn_class, от 0 до 1.
Не задавай вопросов и не предлагай изменений.
```
