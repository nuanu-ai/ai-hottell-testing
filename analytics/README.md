# Аналитическая часть — спецификации

Владелец — Александр Саломатов. Здесь описано, **что** считает анализатор и **как это определено**; реализацию, хранение и интерфейсы делает техническая часть. События сессий лежат в ClickHouse (`otel-lab`); где какие поля — [model.md §4](model.md#4-где-это-в-clickhouse). Концепт — [docs/spec/analyzer.md](../docs/spec/analyzer.md), путь пользователя — [docs/spec/user-flow.md](../docs/spec/user-flow.md), план — [docs/plan/analytics-implementation.md](../docs/plan/analytics-implementation.md).

| Файл | Что определяет | Кто пользуется |
|---|---|---|
| [model.md](model.md) | логическая модель: сущности и поля, которые нужны правилам и метрикам, откуда они берутся в событиях агентов, как нормализуются; сущности результатов анализа | реализация нормализации, хранилища и MCP; сверка полей в ClickHouse |
| [catalogue.yaml](catalogue.yaml) | 13 детекторов MVP: сигнал, исключения, параметры, evidence, затраты, severity, действие, метрика проверки | реализация детекторов; skill |
| [metrics.md](metrics.md) | главная метрика, вердикт, затраты эпизода, цена контура, сэкономленное время, baselines, сравнение с командой | ядро, дашборд |
| [criteria.md](criteria.md) | классы задач, критерии готовности и проверки, которые распознаются в данных | вердикт, skill |
| [quick-review.md](quick-review.md) | быстрый разбор хода по хуку `Stop`: вход, выход, правила, промпт | запуск из хука, хранилище |
| [skill/SKILL.md](skill/SKILL.md) · [skill/schemas.json](skill/schemas.json) | глубокий разбор — содержание skill `session-retro`; схемы выходов обоих разборов | упаковка skill, MCP, хранилище |
| [contract-example.md](contract-example.md) · [examples/](examples/) | сквозной пример: сессия из MCP `hottell` → разбор → разметка → изменение → проверка; синтетические JSON | интерфейс между аналитической и технической частью, приёмка хранилища |
| [dashboard.md](dashboard.md) | три экрана MVP: виджеты, ранжирование, тексты, действия; что появится после · демо — [demo/dashboard.html](../demo/dashboard.html) | дашборд |
| [share-pack.md](share-pack.md) | что участник отдаёт в командный вид; определения сравнения | share-pack, экран «Команда» |

Статус всех файлов — `draft`: поля событий взяты из документации агентов и кода `hottell`, не из живых данных; сверяются по ClickHouse на первых своих сессиях. Реальные сессии, разметка и отчёты в git не попадают.

**Приёмка реализации.** Детектор принят, когда на `acceptance/` все случаи дают ожидаемый результат, а на реальном корпусе доля снятых человеком эпизодов не выше 50 % после калибровки порогов.
