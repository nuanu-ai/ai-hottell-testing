# Сквозной пример: от сессии до внедрённого изменения

Один синтетический случай, на котором аналитическая и техническая части сверяют интерфейс. Реальные сессии в git не кладём.

```
сессия (MCP hottell: session_read)
  → глубокий разбор (skill session-retro)
  → разбор и рекомендации (JSON по skill/schemas.json)
  → подтверждение и разметка человека
  → применение одной рекомендации: diff → подтверждение → запись в журнал
  → следующая похожая сессия: изменение используется? эпизод исчез?
```

## 1. Вход — сессия

[examples/session-read.json](examples/session-read.json) — ответ `session_read` MCP `hottell` в его общей модели событий: `user_message`, `assistant_message`, `tool_call`, `tool_result`, `turn_start/end`. Сессия Codex «Сверь возвраты за август»:

- ход 0: агент сверил все способы оплаты и написал «Готово»;
- ход 1: человек поправил — «только карточные, я же всегда так прошу»; агент трижды запустил один и тот же скрипт с одной ошибкой, потом отфильтровал вручную и написал «суммы сошлись с контрольной» без проверки.

Соответствие полям [model.md](model.md): `user_message` → `HumanTurn`, `assistant_message` последнего хода → `AgentTurn.final_message`, пара `tool_call` / `tool_result` по `call_id` → `ToolCall`, `is_error` → `success = false`, `turn_start/end` → границы хода.

## 2. Выход — разбор

[examples/review.json](examples/review.json) — выход skill, валиден по [skill/schemas.json](skill/schemas.json):

| Что | Значение |
|---|---|
| Реплика 1 | `correction`, инструкция «Сверять только карточные возвраты» |
| Эпизоды | D03 — три одинаковых вызова `c2–c4` с одной ошибкой; D10 — то же указание в третьей сессии сверки; D05 — «суммы сошлись» без проверки |
| Мнение о результате | `unknown`: проверки итогов нет; вопрос человеку — «принят ли результат» |
| Рекомендации | D10 → строка в AGENTS.md проекта, `repeated`, уверенность 0.8; D05 → подсказка в hook `Stop`, `single_session`, уверенность 0.5 |
| Вне каталога | «у скрипта нет параметра `--method`, агент угадывал трижды» |

## 3. Разметка человека

Человек отвечает на вопрос и отмечает эпизоды. В пилоте — строки в `local-data/labels.jsonl`:

```json
{"type": "label", "session_id": "demo-0001", "task_ref": "refunds-2026-08", "goal": "Сверка карточных возвратов за август", "done_criteria": ["сумма совпадает с контрольной", "отчёт принят бухгалтерией"], "outcome": 2, "rework_min": 10, "share": "none", "send": false}
{"type": "review", "session_id": "demo-0001", "pattern_id": "D03", "by": "human", "decision": "confirm"}
{"type": "review", "session_id": "demo-0001", "pattern_id": "D10", "by": "human", "decision": "confirm"}
{"type": "review", "session_id": "demo-0001", "pattern_id": "D05", "by": "human", "decision": "confirm"}
```

Вердикт по разметке — `partial` (результат принят с доработкой 10 минут).

## 4. Применение и журнал

Человек применяет рекомендацию D10. Агент показывает изменение и вносит его после подтверждения:

```diff
--- AGENTS.md (проект finance-ops)
+ Сверка возвратов — по умолчанию только карточные платежи, если в задаче не сказано иначе.
```

Запись в журнал (`local-data/journal.jsonl` в пилоте):

```json
{"proposal": "demo-0001/D10", "implemented_at": "2026-09-30", "target": "AGENTS.md проекта finance-ops", "status": "implemented"}
```

## 5. Проверка на следующей похожей сессии

Следующая сверка — сессия `demo-0003`. Глубокий разбор проверяет: указание «только карточные» не повторялось (сигнал использования), эпизода D10 нет, результат принят, доработка — по разметке. Запись в журнал:

```json
{"proposal": "demo-0001/D10", "usage": {"signal": "instruction_repeats", "count": 0, "since": "2026-09-30"}, "effect": {"metric": "instruction_repeats", "before": 3, "after": 0, "n_before": 3, "n_after": 1, "method": "before_after"}, "status": "preliminary"}
```

Статус — «предварительно»: одна сессия после внедрения, задачи сопоставимы, но не одинаковы.

## 6. Где это живёт

| Что | Пилот | Фаза 2 |
|---|---|---|
| Сессия | локальный транскрипт через MCP `hottell` | то же + события на сервере |
| Разбор и рекомендации | `local-data/retro/<session_id>.json` | хранилище результатов через MCP ([model.md §2](model.md)) |
| Разметка, журнал | `local-data/labels.jsonl`, `local-data/journal.jsonl` | то же хранилище |
| Показ | карточка в аналитической сессии | дашборд: «Где плохо» — подтверждённые эпизоды; «Сессии» — ходы и эпизоды; «Рекомендации» — рекомендации и журнал ([dashboard.md](dashboard.md)) |

`local-data/` — в `.gitignore`.
